# can't add lesson. enrollments > lessons > +

## Problem
iPhone app, enrollment lessons list ("+" button below the scheduled-day cards — reachable from a group's enrollment schedule and from Group Home's lessons view). Tapping "+" shows the "Add a new lesson?" dialog; confirming always fails with the top error banner **"Couldn't add the lesson"**. Guaranteed failure, not intermittent: `EnrollmentActions.addScheduledLesson` POSTs an **empty body** to `POST /api/enrollments/:id/schedules`, but the endpoint requires `lessonId` (zod) — its semantics are "schedule an existing program lesson (copying its activities), dated by walking forward from the last schedule along the enrollment's enabled days." The request 400s every time. "Fixed" looks like: confirming the dialog schedules the next not-yet-scheduled lesson from the study at the end of the enrollment; when every program lesson is already scheduled, the user gets a clear message (or the "+" is disabled) instead of an error banner.

## Root cause
`EnrollmentActions.swift:414-419`: `addScheduledLesson` sends `body: [:]` to `POST /api/enrollments/:id/schedules`, whose zod schema (`enrollments.ts:4642-4645`) requires `lessonId: uuid`. Every invocation 400s → both callers surface "Couldn't add the lesson". The client was never wired to choose which program lesson to schedule.

## Verification
1. **Code-level proof:** `EnrollmentActions.swift:417` (`body: [:]`) vs `enrollments.ts:4642-4645` (`lessonId` required) — the request can never validate.
2. **Manual repro (simulator + local stack):** open a group → enrollment → lessons → tap "+" → confirm "Add lesson". Observed: red "Couldn't add the lesson" banner (as screenshotted). Fixed = a new day card appears at the end of the list, dated per the enrollment's enabled days; when all program lessons are already scheduled, a clear message instead of a failure banner.
