# difficult to use

## Problem
iPhone tag entry (shared `TagInput` component; the report/screenshot is the **Edit Program** pane on ProgramHomePage). Committing a tag via the keyboard's check/return key adds the tag but **drops keyboard focus**, so entering multiple tags requires tapping back into the field between every tag. Since tags are naturally entered in batches, the flow should keep the cursor in the tag field after each commit ("have the cursor already in the tag box so I could start typing another tag"). "Fixed" looks like: after submitting a tag with the return key, the field stays focused with the keyboard up, ready for the next tag, for as many tags as the user wants to enter.

## Reports (verbatim)
- (2026-07-25, Scott Stickane) "When adding a tag, I need to click on the check (enter) button, then I need to click back into the field to add another. If I really wanted to use this, I would want to have the course already in the tag box so I could start typing another tag, b/c tags work best in groups" ("the course" = autocorrect for "the cursor")

## Root cause
`TagInput.swift:50-51`: the tag `TextField` commits via `.onSubmit` with `.submitLabel(.done)`; SwiftUI's default submit behavior resigns first responder, and nothing restores `isFocused` after `addTag`. Each committed tag therefore dismisses the keyboard, forcing a re-tap for the next tag.

## Verification
1. **Code-level proof:** `TagInput.swift:46-54` — no `isFocused = true` after submit anywhere in the component.
2. **Manual repro (simulator):** open a program → Edit Program → tap the tag field → type a tag → tap the keyboard's ✓. Observed: tag pill appears, keyboard dismisses/focus leaves. Fixed = keyboard stays up, cursor still in the field, typing immediately starts the next tag; repeat several tags hands-free. Same check applies on Create Program and the media detail tag editor.
