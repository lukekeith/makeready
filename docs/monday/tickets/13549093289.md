# Misaligned

## Problem
On a 402pt-wide iPhone (17 / 17 Pro class; the reporter says "iPhone 18"), the UI 2.0 home dashboard (Home tab) is wider than the screen: the TopNav cards, section headers (Following, Overview, Activity), the "+" buttons and "Jump to today" are clipped on both edges, about 19pt each side. Two charts pin a fixed design width wider than the screen: the Activity chart (C-026 DualSeriesBarChart) at 440pt and the Sessions chart (C-030 TimeActivityChart) at 438pt. The section's VStack takes its widest child's width and is centred in the 402pt viewport, so the whole page shifts left and clips. Fixed looks like this: on any iPhone width (375–440), the home dashboard's leading content sits at its 16pt margin, trailing controls are fully visible, and both charts fill the width they are given.

## Reports (verbatim)
- (2026-11-13) "Edges of the screen are cut off on iPhone 18"

## Affected areas

### In scope
- **Platform:** iphone
- **Screen:** UI 2.0 home dashboard — `iphone/MakeReadyUI/Screens/Home/HomeDashboardScreen.swift` (d2m-built, screen `home-dashboard`)
  - `:197` `dualChartWidth: CGFloat = 440` and `:366` `.frame(width: Self.dualChartWidth, height: Self.dualChartHeight)` on C-026 DualSeriesBarChart. The component is already width-driven (`iphone/MakeReadyUI/DualSeriesBarChart.swift:15-18, 266-300` GeometryReader), so only the frame changes.
  - `:200` `timeChartWidth: CGFloat = 438` and `:413` `.frame(width: Self.timeChartWidth, …)` on C-030.
- **Component(s):** C-030 TimeActivityChart — `iphone/MakeReadyUI/TimeActivityChart.swift:54` `Geometry.width = 438`, used at `:127, :148, :181`. The bars sit on a 5pt pitch (88 bins at 438). To fill a narrower width, the bin count or pitch must follow the given width. This is a contract change (C-030 §2 "Root: 438 wide"), so it goes to d2m.
- **App-side mapper:** `iphone/MakeReady/UI2/Containers/Home/HomeDashboardMapper.swift:64` `fixed(r.bins, count: 88)`. It fixes the bin count at 88, which must match however C-030 sizes to its width.

### Cross-app impact
None: iPhone-only, no API or schema change. Both files are d2m-built. The C-026 frame line is a home-dashboard screen change, and C-030's width-driven bars are a component contract change d2m must make (handover). The home-dashboard chat fails with exit 1 (2026-11-09, 2026-11-13), so route through the activities-editor chat with `@C-030`.

## Root cause
`HomeDashboardScreen.swift:366` (440) and `:413` → `TimeActivityChart.swift:54/127/181` (438) give children of the section's VStack fixed widths above the device width. The VStack sizes to 440 and is centred in the 402pt viewport: (440 − 402) / 2 = 19pt off each side, the whole page's 16pt margin and a little more. The design was only ever frozen at 440 (iPhone Pro Max).

## Verification
- **Code-level proof:** the two fixed frames above. Any device narrower than 440pt reproduces it.
- **Capture:** render the home-dashboard screen `default` state at 402×874 (iPhone 17 Pro) and at 375 (SE / mini). Leading text must start at x=16, and the trailing "+" must be fully on screen.
- **Manual:** run a dev build on an iPhone 17 / 17 Pro (or the iPhone 17 Pro simulator) → Home tab → the header text and "+" buttons must not touch the screen edges; scroll to Activity and Sessions and check that both charts end inside the screen.
