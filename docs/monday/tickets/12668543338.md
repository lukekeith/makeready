## Root cause

**A — a `@State` snapshot that never refreshes.** The highlight action-menu sub-view receives the
parent's note dictionary as a plain value and seeds its own state with
`State(initialValue: savedNoteMarkdownByHighlight)` (`EditExegesisActivityPage.swift:982`). SwiftUI
applies `State(initialValue:)` **only on first construction of that view identity** — later re-inits
with fresher values are discarded. The parent hydrates the real notes asynchronously afterwards
(`:567`, from `loadExegesisHighlights`) and on note creation (`:822`), but those writes land on the
parent's copy at `:185` and never reach the child. `currentNoteHasContent` (`:1305`) therefore reads an
empty dictionary and the button stays "Add note" (`:1312`) for a highlight that demonstrably has a
note. **verified in code (2026-08-02)**

**B — `.optional()` is not `.nullable()`.** `StudyJoinController.php:62` deliberately writes
`$lesson['organizationId'] ?? null` to the session, so when the lesson payload carries no organization
the controller posts a literal `null` (`:148`). The server schema is `z.string().optional()`
(`members.ts:423`), which permits `undefined` but not `null`, so zod fails with its stock message
**"Expected string, received null"** — returned raw at `members.ts:519`, passed through by Laravel, and
printed to the member by `join-phone-island.vue:105`. Two independent defects: the null is sent, and a
validation internal is shown to an end user. **verified in code (2026-08-02)**

**D — every escape from highlight mode is disabled except one unlabeled glyph.** Entering highlight
mode sets `highlightingBlockId`, which then:
- hit-test-disables the **entire header**, including *Cancel* and *Done* (`:386-387`) — the dimming is
  visible in the screenshot;
- hit-test-disables **every editable block** (`.allowsHitTesting(highlightingBlockId == nil)`);
- leaves exactly two exits: re-tapping the 24×24 highlighter glyph (`:706`) and tapping a **different
  locked block** (`:630` — the only other place `highlightingBlockId` is cleared).

Scott's activity had **one** locked block (the John 1:1-3 verse) and one editable text block, so the
second exit did not exist for him and the first is an unlabeled icon. There is no background
tap-to-dismiss and no explicit "done highlighting" control, so the app genuinely had to be killed.
**verified in code (2026-08-02)**

**C — fixed.** `d63eb1c` (2026-07-30, on `main`, filed under monday#12668501065) reclassified the
message as an `AppMessageKind.notice` (neutral, no retry — `AppState.swift:33-40`) and, more usefully,
disabled the "+" button with inline text "Every lesson in this study is scheduled"
(`EnrollmentSchedulePage.swift:339-349`) so the dead-end is stated before the tap rather than after.

exits highlight mode"* — which had only ever been wired to other **locked** blocks.
