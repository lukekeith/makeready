# shouldn't be

## Problem
Multi-report ticket from the V1.1.3 (320) iPhone TestFlight release board, group
"UI issues". THE ACTIONABLE SUB-ISSUE (per Luke's 2026-07-28 directive): on the
**Edit Program** pane, the cover-image well overlays the large ghost text "Add
program name" when the program has a cover image but the picker's name binding
is empty — yet tapping the well opens the **image selector**, not a name input.
The text is a misleading call-to-action. Fixed = the has-image branch of the
cover well shows small, accurate helper text **"Tap to select cover image"**
(or nothing), on BOTH platforms (the web LeaderApp twin has the identical
branch). Sub-issues 2–3 (org-wide member/group edit visibility) are recorded
below but are OUT OF SCOPE here — see Explicitly out of scope.

## Root cause
`CoverImagePicker` was designed with a dual-purpose overlay (program name
display + call-to-action). The has-image/no-name branch
(`CoverImagePicker.swift:138-143`, `cover-image-picker.vue:105-107`) chose
"Add program name" as the CTA even though tapping the well opens the PHOTO
picker (`editableView` → `showPhotoPicker = true`, Swift :43-49) — the copy
promises a rename affordance that the tap target doesn't provide.

## Verification
- **Code-level proof (strongest):** `iphone/MakeReady/Components/Input/CoverImagePicker.swift:140`
  renders `Text("Add program name")` inside a Button whose action is
  `showPhotoPicker = true` (:44-45). Same string at
  `client/resources/js/components/card/cover-image-picker/cover-image-picker.vue:106`.
  No fix commits since 2026-07-01 touch either file (only 9694cb2, unrelated).
- **Manual repro (web):** /admin → Library → program → gear → Edit Program on a
  program WITH a cover whose picker name binding is empty → the well shows
  "Add program name"; clicking opens the file picker.
- **Fixed looks like:** small helper text "Tap to select cover image" (styled
  like the existing secondary s13 white@0.4 hint) or no text, in that branch,
  both platforms.
