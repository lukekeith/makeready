# can't click

## Problem
iPhone app, **enrollment** day editor (EditEnrollmentDay — "Day 1" modal with an ✕ close icon, reached via a scheduled lesson: Group → enrollment → Edit lessons, or Home/Calendar → tap a scheduled lesson). Tapping the YouTube and Exegesis activity rows does nothing — no editor opens, no visual response. Read, Write (user input), and Video rows respond normally. This is not a hit-testing bug: the tap handler explicitly no-ops for those types because the enrollment context has no YouTube/Exegesis editors — they exist only in the program (curriculum) sibling `EditDay`. Worse, the shared AddActivityMenu still offers YouTube and Exegesis in the enrollment context, so a leader can add an activity they can then never configure. "Fixed" looks like: tapping the YouTube row slides to a YouTube editor (URL + segment range) and tapping the Exegesis row slides to the exegesis editor (passage + highlights), both persisting to the scheduled activity, exactly as the program-side EditDay does.

## Reports (verbatim)
- (2026-07-25, Scott Stickane) "Lessons > edit activity > I can't click on the bottom 2 to edit. The others I can but the YouTube video and exegesis doesn't work"

## Root cause
`EditEnrollmentDay.swift:336-341` and `:461-498`: the enrollment day editor was modeled on `EditDay.swift` but only the READ and USER_INPUT editors were ever wired for `ScheduledActivity`; YOUTUBE and EXEGESIS taps intentionally fall through to `default: break`, so the rows are dead. The supporting write API is also missing: `PATCH /api/scheduled-activities/:id` (`enrollments.ts:3041`) accepts no youtube fields, and exegesis-highlight CRUD is program-activity-only (`programs.ts:2949`). The data model already carries all needed columns, and enrollment creation copies youtube/exegesis content from the source program (`enrollments.ts:302-336`), so these activities appear in enrollments but can never be edited there.
