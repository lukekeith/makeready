## 📱 iPhone app — user-facing

### Highlighting — the Exegesis editor (biggest change; most regression risk)

- **Highlights now commit when you lift your finger, never on a timer.** Previously a highlight
  could be created mid-gesture while you were still dragging.
  **QA:** press and hold on a verse, drag to extend, and keep holding for several seconds *without
  releasing* — nothing should be saved until you let go. Drag back and forth first; the span should
  follow your finger and only the final position should stick.
- **Selection snaps to whole words.** You can no longer end up with half a word selected.
  **QA:** start a drag in the middle of a word and release in the middle of another — the saved
  span should expand outward to cover both words completely. Specifically try a word with an
  apostrophe (**"Lord's"**) — it must stay whole, not split at the apostrophe.
- **Notes are no longer lost when highlights merge.** This was the headline bug
  (monday#12708759849). Drawing a highlight across existing ones absorbs them into a single span.
  **QA — the important one:** add two separate highlights on the same passage and give each a
  *different* note. Then highlight across both. The resulting single highlight must contain **both
  notes**, one after the other. Nothing may be silently dropped.
- **No more page jump on the second highlight.** The scroll position used to snap back to the
  previous highlight's location.
  **QA:** make a highlight, scroll somewhere else, then make a second one. The page must not jump.
- **Re-highlighting text you previously highlighted and deleted now works.** It used to fail
  silently and permanently.
  **QA:** highlight a phrase → delete the highlight → highlight the *same* phrase again. It must
  work the second time.

### Highlighting — the Read activity editor

- **Selection changed from tapping a whole verse to press-and-hold word selection**, matching the
  Exegesis editor. **This is a deliberate behaviour change, not a bug.**
  **QA:** press and hold to select words — you should now be able to highlight *part* of a verse,
  which was impossible before. A single **tap** no longer selects a verse; it only re-opens an
  existing highlight's editor.
  ⚠️ **This surface has scroll-locking during selection for the first time ever** — watch for any
  page jump or stutter while dragging.
- **Highlight colour changed from purple to a yellow-green (lime).** Applies to saved highlights
  everywhere.
  **QA:** confirm existing highlights render in the new colour and that none have disappeared.
- **Verse cards keep their rounded corners** after highlighting (monday#12701776858 —
  a regression from the previous release's fix).
  **QA:** highlight inside a Bible verse card and confirm the corners stay rounded.

### Highlighting — the Bible reader

- The Bible reader shares the same selection engine now, though its behaviour should be unchanged.
  **QA — least-exercised surface in this release, please give it real attention:** select a passage
  and confirm you still get a passage reference back, the verse circles still work, and there is
  **no scroll jump** while dragging.

### Highlights are stored server-side now

- Read-activity highlights moved from being embedded in the lesson content to their own records.
  Existing highlights were migrated.
  **QA:** open activities that already had highlights and confirm every one still shows, in the
  right place, with its note.
  **QA:** force-quit and relaunch the app, then reopen the same activity — highlights must survive.

## 🔌 Backend / API — affects in-app behavior

- **New highlight endpoints** backing all of the above (create / update / delete / list), now
  allowed for **Read** activities as well as Exegesis. The old Exegesis-only endpoints still work
  and return the old response shape, so **an older build of the app keeps functioning**.
- **Multi-block Read activities are addressed correctly.** A Read activity can have several passage
  blocks; the API now returns every block rather than assuming one.
  **QA:** on a Read activity with several verse blocks, highlight text in more than one block and
  confirm each highlight stays on its own block.
- **Existing highlight data was migrated** (67 spans converted, run on local only so far) with a
  rehearsed rollback. **QA is the real check that nothing was lost.**
- **Lesson content hashing was fixed** so this migration does not mark every enrolled group's
  lessons as stale.
  **QA:** confirm enrolled groups' lesson schedules look normal and nothing appears
  re-synced/reset.

## Known gaps worth telling QA about

1. **Older builds were never actually tested against the new server.** The data and response shapes
   they read are proven unchanged, but no pre-release binary was run to confirm it. **If a tester on
   an older TestFlight build reports missing Read highlights, that is the first thing to
   investigate.**
2. The **Bible reader** is the least-exercised surface of the three that changed.
3. Highlight-data migration has been applied to **local only**, not production.
