## 📱 iPhone app — user-facing

### Study editors — Read activity

- **Highlight mode shows what you selected, and no longer sprouts stray handles** — tapping the
  highlighter on a Bible-verse block used to leave two floating text-selection grab handles with
  nothing between them, because the selection fill was drawn by the system and got wiped on every
  redraw. The block now paints the selection itself (lime wash), and the system selection is off
  entirely, so no handles are created (monday#12668695071).
  **QA:** Read activity containing a verse block → tap the highlighter glyph top-right of the block
  → the verses you tap fill with a lime wash that *stays* while you keep tapping or typing
  elsewhere. **No lollipop/grab handles should appear anywhere.** Tap a selected verse a second
  time → the style picker opens (Bold / Highlight).
- **Highlight mode now tells you what to do** — a hint reads *"Tap verses to select, then tap again
  to style"*. Previously the only signal was a purple border.
  **QA:** Enter highlight mode → the hint is visible above the verses; leave the mode → it's gone.
- **You can get out of highlight mode** — Cancel/Done stayed dimmed *and* unresponsive, so an
  activity with a single verse block had no exit but force-quitting the app (monday#12668543338 D).
  **QA:** Read activity with **one** verse block → enter highlight mode → tap Cancel (or Done, or
  empty background) → you leave highlight mode and **nothing is saved or discarded**. Tap again →
  the button does its real job.

### Study editors — Exegesis activity

- **Notes moved to a full-screen editor** — the note used to live in a bottom sheet that sized
  itself from the keyboard, so the field resized underneath you while typing and Cancel/Done fought
  the keyboard toolbar. It's now a fixed full-screen surface (Apple Books / Kindle shape): header
  actions, the quoted passage pinned above the note, dot + swipe navigation across the block's
  highlights, keyboard overlaying rather than reflowing.
  **QA:** Exegesis activity → tap a highlight → **+ Add note** → the editor opens full-screen.
  Type past the bottom of the field: **nothing under your cursor should move or resize.** Swipe
  left/right (or tap the dots) to move between highlights on that block — unsaved text on each one
  should survive the trip. **Tapping the background must NOT dismiss it** (it's holding drafts).
  Cancel discards, Save persists.
- **A saved note can actually be edited** — the button read "Add note" even for a highlight that
  already had one, and the saved note was unreachable (monday#12668543338 A).
  **QA:** Add a note to a highlight → save → leave the activity and reopen it → tap that highlight
  → the button reads **Edit note** and opens with your text in it.

### Program Home — new **Analytics** tab

- **Third tab alongside Lessons and Enrollments** — KPI grid, top groups, recent-activity line and a
  heatmap, with a Week/Month/Year toggle and a proper empty state when a study has no enrollments or
  no activity yet. Partial build (sections 1/3/4 of the spec).
  **QA:** Open a study → **Analytics**. On a study with real enrollments: KPIs populate, the
  Week/Month/Year toggle re-renders the charts, top groups list only groups with completions. On a
  brand-new study: you get the empty state, not a broken/blank tab.
  **⚠️ Requires the server deploy + migrations below** — against an undeployed server this tab
  fails to load.

### Enrollment scheduling

- **"All lessons are already scheduled" is a notice, not an error** — it used to appear as a red
  error bar after the fact; the "+" button is now disabled up front with inline text explaining why
  (monday#12668501065).
  **QA:** Enrollment where every lesson is scheduled → the "+" row is disabled and reads *"Every
  lesson in this study is scheduled"* — no red bar after tapping.
- **Preview modal explains a failed load** instead of showing an empty sheet.
  **QA:** Open a lesson preview with the network off → you get an explanatory message, not a blank
  modal.
- **Enrollment date edits derive the start date from the actual schedule** — a fully-locked
  enrollment could persist `startDate > endDate`; the preview now warns when a reschedule can't move
  any lessons (server-side, monday#12661792842). Existing bad rows were repaired by a one-off.
  **QA:** Edit dates on an enrollment whose lessons are all locked → you get a warning that nothing
  can move, and the saved dates stay sane afterwards.

### Bible reader

- **Gutter verse numbers survive chapter swipes** — they could vanish after swiping between chapters
  (monday#12661826210).
  **QA:** Open the Bible reader → swipe through several chapters back and forth → the verse numbers
  in the left gutter are present every time, with no stale numbers left from the previous chapter.

### Data freshness across screens

- **Tags, group leaders, members, enrollments, posts and join requests now come from one shared
  store** rather than each screen keeping a private copy that could go stale. The visible payoff is
  the reported bug: a newly added tag didn't show up in the Library tag filter
  (monday#12668501065 J).
  **QA (highest value here is cross-screen consistency):**
  - Add a tag to a study → **Library → Programs → tag filter** lists it immediately, no app restart.
  - Approve or decline a join request → the request list, the members list and the badge/count all
    agree without backing out and reopening.
  - Post in a group, then scroll the feed → no duplicated or missing posts at the paging boundary.
  - Change a group's leaders → every screen showing leaders reflects it.
